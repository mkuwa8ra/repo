curlは1996年、IRCボットのために為替レートを取りに行く小さなスクリプトとして生まれた。今では火星のヘリコプターから自動車、ゲーム機、そしてあなたのWindows端末まで、推定100億台以上のデバイスで動いている。このページではcurlの歴史・名前の由来・内部構造・通信の仕組み・Windowsでの注意点までを一気に解説する。

overview

curlとは何で、何ではないのか

「curl」という単語は実は3つの異なるものを指している。混同されがちなので、まず整理する。

CLI TOOL

curl（コマンド）

ターミナルやバッチファイルから実行する単体の実行ファイル。URLを指定してデータを送受信する。スクリプトに組み込みやすく、パイプで他のコマンドと連結できるUnix的な設計。

curl https://example.com
LIBRARY

libcurl（ライブラリ）

2000年に切り出されたC言語のライブラリ本体。実際の通信処理はすべてここに入っている。curlコマンドはlibcurlの薄いラッパーに過ぎない。50以上の言語からバインディング経由で呼び出せる。

curl_easy_perform(handle);
PROJECT

cURLプロジェクト

上記2つを開発・保守するオープンソースプロジェクト全体の名称。表記は小文字curlが正式（大文字CURLはPHPバインディングの定数名として紛れて使われることがある）。

ETYMOLOGY

名前の由来

"Client" + "URL" = cURL。語感が良く、catのようにUnix流儀でURLを標準出力に流すツールにしたかった、とStenberg本人が回想している。当初はhttpget→urlgetという名前を経て、アップロード機能が増えたことで再命名された。

1996 — present

28年のタイムライン

curlの歴史は一人のスウェーデン人エンジニアの「ついカッとなって自動化した」という個人的なモチベーションから始まり、Internet標準の一部にまで成長した記録でもある。

1996年11月

HttpGet 0.1 — 発端

ブラジルの開発者Rafael SagulaがHttpGetという小さなHTTPクライアントを公開。Daniel StenbergはAmiga系IRCチャンネル用のボットを書いていて、為替レートを毎日自動取得したいと考え、このツールを拡張し始める。

1996年12月〜1997年

urlget への改名

StenbergがHttpGetの保守を引き継ぎ拡張。GopherやFTPからもレートを取得する必要が出てきたため、HTTP専用を示す名前を捨てて「urlget」に改名。プロキシ対応なども追加された。

1998年3月20日

curl 4.0 — 正式デビュー

FTPアップロード機能の追加により「get専用」の名前が実情と合わなくなり、最終的に「curl」へ改名。約2,200〜2,400行、コマンドラインオプション25個ほどの規模で初版リリース。バージョン番号はurlgetの3系を引き継ぎ4.0からスタートした。

2000年夏

libcurl の誕生

内部構造を大きく見直し、他のアプリケーションやプログラミング言語から呼び出せるAPIとしてlibcurlを切り出した。これが転機となり、curlは単なるCLIツールから「インターネット転送のデファクトAPI」へと役割を広げていく。

2001年9月

Mac OS X 10.1 に標準搭載

Linux以外のOSで初めて標準ツールとして採用された大きな節目。同時期にDebianパッケージ化（1999年）も完了し、UnixおよびBSD系の定番ツールとしての地位を確立していた。

2005年3月22日

HTTP/1.1 対応・持続的接続

curl 7.7でHTTP/1.1サポートを実装し、libcurlにpersistent connection（接続の再利用）機能が入る。コード規模は24,000行に到達。

2017年12月

Microsoftが採用を発表

Windows 10のInsider Build 17063でcurlがデフォルト搭載されることが発表される。20年以上を経て、curlは主要OSすべてに標準搭載される存在になった。詳細は後述。

2018年4月

Windows 10 version 1803 に正式搭載

一般ユーザー向けのWindows 10アップデートでcurl.exeが標準搭載され、数億台規模のWindows端末に一気にcurlが行き渡った。

2021年4月

火星ヘリコプター「Ingenuity」での利用が確認

GitHubがMars 2020ヘリコプター・ミッションへのオープンソース貢献者バッジを配布した際、curlのコントリビューターにもバッジが付与され、curlが地球外で稼働していることが事実上確認された。

2024年〜

HTTP/3・QUIC・耐量子暗号への対応

HTTP/3とQUICのサポートが安定化し、ポスト量子暗号（PQC）のハイブリッドアルゴリズム対応の検討も進む。リリースは8週間ごとのサイクルを維持し続けている。

internal structure

curlコマンドの内部構造

あなたが打つ curl ... というコマンドは、実際にはlibcurlという巨大なライブラリへの薄いラッパーでしかない。重い処理はすべてlibcurl側にある。

curl.exeはWindowsではOSの暗号API「Schannel」を、Linuxでは多くがOpenSSLを使う、というようにビルド時の選択でTLS実装が変わる。

easy interfaceは1回の転送を順番に処理するシンプルなAPIで、curl_easy_init() → curl_easy_setopt() → curl_easy_perform() → curl_easy_cleanup() という4ステップで完結する。multi interfaceはこれを複数同時に、ノンブロッキングで動かすための仕組みで、ブラウザやダウンローダーのような並行接続を必要とするソフトウェアで使われる。

request lifecycle

curl https://... の舞台裏

1行のコマンドが実行されてから画面に結果が表示されるまで、curlは何段階もの処理を踏んでいる。

01URL解析

スキームとホストの分解

入力された文字列をスキーム（https）・ホスト名・パス・クエリに分解し、どのプロトコルハンドラを使うか決定する。

02名前解決

DNSルックアップ

ホスト名をIPアドレスに変換する。OSのリゾルバを使う方法と、curl組み込みの非同期リゾルバ「c-ares」を使う方法（AsynchDNS機能）がある。結果はlibcurl内部でキャッシュされる。

DNS-over-HTTPS対応可カスタムDNS指定可
03TCP接続

3ウェイハンドシェイク

解決したIPアドレスへSYN→SYN/ACK→ACKの手順でTCP接続を確立する。HTTP/3を使う場合はここがQUIC（UDPベース）に置き換わる。

04TLSハンドシェイク

暗号化チャネルの確立

httpsの場合、ここでTLSハンドシェイクが入る。サーバー証明書を取得し、内部のCA証明書ストアと照合して正当性を検証。Windows版curlはこの部分をOS標準のSchannelに委ねている。

証明書検証ECH対応セッション再利用
05リクエスト送信

メソッド・ヘッダー・ボディの構築

指定したHTTPメソッド（GET/POST等）、-Hで追加したヘッダー、-dで渡したボディをワイヤーフォーマットに組み立てて送信する。

06応答受信

ステータス・ヘッダー・ボディの解析

サーバーからのレスポンスを受信し、ステータスライン・ヘッダー・ボディに分解。リダイレクト（3xx）の場合は-L指定があれば追従し、再度02〜06を繰り返す。

07出力

標準出力 or ファイルへ書き出し

デフォルトではボディをそのまま標準出力（stdout）に流す。catコマンドのように振る舞わせたいというStenbergの当初の意図がここに表れている。-oでファイル保存に切り替えられる。

tls backends

なぜ環境ごとに挙動が違うのか

curlはTLS（暗号化通信）の実装を1つに固定していない。ビルド時に選んだ「バックエンド」によって、対応する暗号スイートや証明書ストアの扱いが変わる。これが「同じcurlコマンドでも環境によって動作が違う」と感じる主な原因のひとつ。

バックエンド特徴
OpenSSL最も広く使われる実装。Linux配布版の大半が採用。
SchannelWindows OS標準の暗号API。Microsoft配布のcurl.exeが採用し、証明書管理をWindowsの証明書ストアに委ねる。
wolfSSL組込み機器向けの軽量実装。Stenberg自身が現在所属する企業の製品でもある。
GnuTLS / mbedTLSライセンス上の理由やフットプリントの小さい用途で選ばれることがある。
rustlsRust製の比較的新しい実装。メモリ安全性を重視する文脈で採用が進む。
on windows

Windowsでcurlを使うときの注意点

Windowsユーザーが最初にぶつかる罠は、ほぼ確実に「PowerShellのcurlは本物のcurlではない」という事実。

⚠ ALIAS TRAP

PowerShellのcurlは別物

Windows 10 build 1803（2018年4月）以降、C:\Windows\System32\curl.exe として本物のcurlが標準搭載されている。一方でWindows PowerShell（5.1系）には昔から curl という名前で Invoke-WebRequest コマンドレットへのエイリアスが張られており、こちらが優先して呼ばれてしまう。オプションの意味も出力形式もまったく異なるため、Linux/macOSと同じ感覚で curl -O ... のようなオプションを打つとエラーになる。

cmd.exe（コマンドプロンプト）
curl https://example.com

エイリアスが存在しないため、そのまま本物のcurl.exeが呼ばれる。

PowerShell
curl.exe https://example.com

必ず.exeを明示する。エイリアス解除は
Remove-Item alias:curl

⚠ QUOTING TRAP

シェルによって引用符のルールが違う

JSONボディを -d で渡すような場面で特に問題になる。bash系の慣習で書いた '...'（シングルクオート）は、cmd.exeでは特別な意味を持たず文字としてそのまま渡ってしまう。PowerShellでは " のエスケープルールがcmdともbashとも異なるため、同じコマンドをそのままコピペすると壊れることが多い。

bash / zsh（参考・動かない例ではない）
curl -d '{"key":"value"}' URL
cmd.exe で動かす場合
curl -d "{\"key\":\"value\"}" URL

PowerShellではバックスラッシュではなくバッククオート ` でのエスケープや、ここで示した二重引用符の入れ子ルールがさらに異なるため、複雑なペイロードはファイルに書いて -d @body.json のように読み込ませる方が事故が少ない。

ℹ KNOWN LIMITATION

Microsoft配布版は機能が一部削られている

Windows標準搭載のcurl.exeはMicrosoftが独自にビルドしており、TLSバックエンドはSchannel固定。Public Suffix List（PSL）対応が省略されているなど、curl.se配布版や他パッケージマネージャ経由の版と機能差がある。最新機能や完全な機能セットが必要な場合は、winget install curl.curl や choco install curl、またはWSL経由でのインストールが選択肢になる。

セキュリティ面では、発見された脆弱性ごとに詳細なアドバイザリ（影響範囲・該当バージョン・修正方法）を公開する透明性の高い運用を貫いている。バグ報奨金制度（Bug Bounty）も運営し、発見者への謝礼を支払う体制を取る。

2000sWARNlibcurl URLバッファオーバーフロー系の初期の脆弱性が複数報告される。以降、入力処理の堅牢化が継続的に進む。
2014INFO長年使われていなかったGopherサポートにバグが見つかり、一度削除（後に復活）。「使われない機能は脆弱性の温床になる」という教訓的事例。
継続CRITlibcurlは無数のアプリ・OS・IoT機器に組み込まれているため、1つの脆弱性が広範囲に影響する「サプライチェーンの中心」としての側面を持つ。
現在INFOすべての脆弱性に重大度評価・影響バージョン範囲・回避策を付けて公開する方針を継続中。
ubiquity

推定100億台以上での稼働

curlの作者Stenbergは「自分のコードはほぼ確実にあなたの持っているデバイスのどこかで動いている」と語っている。誇張ではなく、実際の採用範囲は驚くほど広い。

MOBILE

スマートフォン

Android/iOSはOS自体としてはlibcurlをAPIとして公開していないため、YouTube・Instagram・Spotify・Netflixなど主要アプリの多くが各自のビルドを内包している。結果、1台のスマホに複数のcurlが入っていることが多い。

DESKTOP / OS

主要OSすべてに標準搭載

macOS（2001年〜）、各種Linuxディストリビューション、Windows 10/11（2018年〜）。デスクトップOSで標準搭載されていない主要環境はほぼ存在しない。

ENTERTAINMENT

ゲーム機・ゲームタイトル

Nintendo Switch、Xbox、PlayStation 5などのゲーム機本体に加え、Grand Theft Auto V、Fortnite、Red Dead Redemption 2などの大型タイトルにも組み込まれている。

EVERYTHING ELSE

自動車・家電・宇宙

20以上の自動車メーカーの「コネクテッドカー」機能、Roku/Apple TVのようなセットトップボックス、プリンターやスマートウォッチなどのIoT機器、そして2021年には火星ヘリコプター「Ingenuity」での稼働も確認された。

governance & future

運営体制とこれから

curlはMITライセンスで配布され、誰でも無償で使用・改変・再配布できる。開発はDaniel Stenbergを中心に、グローバルなボランティアコミュニティがGitHub上で支えている。Stenberg自身は現在wolfSSL社に所属しながらcurlの開発をフルタイムの仕事として続けている。

今後の方向性としては、HTTP/3とQUICの安定運用、そして将来の量子コンピュータによる暗号解読リスクに備えたポスト量子暗号（PQC）のハイブリッド方式対応が進められている。28年間「派手な野望は持たず、ただインターネット転送を良く・速く・確実にする」ことだけを目標にしてきたプロジェクトが、いま最先端の暗号技術の実験場のひとつにもなっている。

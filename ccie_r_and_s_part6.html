Chapter 16: Introduction to IP Multicasting

IPマルチキャストは、単一のソースから選択された複数の宛先へ、ネットワーク上で1つのデータストリームとしてメッセージを送信する技術です [1, 2]。ユニキャストのような重複送信や、ブロードキャストのような無差別な負荷を避け、スケーラブルなソリューションを提供します [1, 2]。

1. マルチキャストIPアドレス

マルチキャストは、IANAによって割り当てられた クラスD（224.0.0.0 ～ 239.255.255.255） のアドレスを使用します [2]。これらは「グループ」を表し、決してパケットの送信元（Source）アドレスとして使用されることはありません [2]。

  • 恒久的なグループ (224.0.0.0 ～ 224.0.1.255):
    • 224.0.0.x: ローカルリンク用。ルーターによって転送されません（例: 224.0.0.5 OSPFルーター）[2]。
    • 224.0.1.x: ネットワーク全体で転送される制御用（例: 224.0.1.39 Auto-RP）[2]。
  • Source-Specific Multicast (SSM) (232.0.0.0/8): ホストが特定のソースからのトラフィックのみを要求するために予約されています [2]。
  • GLOPアドレッシング (233.0.0.0/8): 登録済みAS番号を持つ組織に256個のアドレスを割り当てます [2]。
  • プライベートドメイン (239.0.0.0/8): 管理的スコープ。組織内でのみ使用可能なアドレスです [2]。

2. マルチキャストMACアドレスへのマッピング

レイヤ3のマルチキャストIPアドレスは、NICが受信を判断できるようにレイヤ2のMACアドレスに変換されます [2]。

  • 形式: 01-00-5E で始まるOUIに、IPアドレスの下位23ビット を付加します [2]。
  • 重複の問題: IPアドレスの28ビットのうち5ビットが計算から除外されるため、32個の異なるIPアドレスが同じ1つのMACアドレスにマッピング されます [2]。

3. IGMP (Internet Group Management Protocol)

ホストとローカルルーター間で「どのグループに参加したいか」を通信するためのプロトコルです [3]。

  • IGMPv2 (デフォルト):
    • Membership Query: ルーターがメンバーの存在を確認するために送信（224.0.0.1宛）[3]。
    • Membership Report: ホストが参加を表明。Report Suppression（レポート抑制）機能により、同一グループの別ホストの報告を聞くと自身の報告を中止し、トラフィックを削減します [3]。
    • Leave Group: ホストが退出を通知（224.0.0.2宛）。ルーターはこれを受けると「Group-Specific Query」を送り、他にメンバーがいないか最終確認します [3]。
  • IGMPv3: ソースフィルタリング（SSM）をサポートし、特定の配信元のみを指定できるようになりました [3]。

4. LANにおける最適化技術

L2スイッチはデフォルトでマルチキャストを全ポートにフラッディングしてしまいます。これを抑制するためのツールが3つあります [3]。

  • CGMP (Cisco Group Management Protocol): Cisco独自のプロトコル。ルーターがスイッチに対し「このポートにこのグループのメンバーがいる」とメッセージ（GDA/USAペア）を送って制御します [3]。
  • IGMP Snooping: 標準的な手法。スイッチがホストとルーター間のIGMPメッセージを「盗み聞き」して、自動的にポートを制限します [3]。
  • RGMP (Router-Port Group Management Protocol): ルーター同士が接続されるポートにおいて、不要なマルチキャストトラフィックが流れないように制御します [3]。

基本設定コマンド例

! マルチキャストルーティングの有効化
ip multicast-routing

! インターフェースでのPIM(Sparse-Mode)とIGMPの有効化
interface FastEthernet0/0
 ip pim sparse-mode
 ip igmp version 2

! IGMP Snoopingの有効化（スイッチ側、通常デフォルトで有効）
ip igmp snooping

Chapter 17: IP Multicast Routing

マルチキャストルーティングは、送信元（Source）から複数の受信者（Group）へ効率的にパケットを届けるための仕組みです。本章では、基本的な転送ロジックであるRPFチェックから、PIMの各モード、およびRP（Rendezvous Point）の選定方法について学びます [1]。

1. マルチキャストルーティングの基礎

  • 転送の課題: マルチキャストアドレスはユニキャストルーティングテーブルに存在しないため、通常の宛先ベースの転送ができません。また、パケットのコピーが必要になる点もユニキャストと異なります [2]。
  • RPF (Reverse Path Forwarding) チェック: マルチキャストのループを防ぐための最も重要なチェックです。「パケットの送信元IPアドレスへのルート上のインターフェースからパケットが到着したか」を確認します。これに合格しないパケットは破棄されます [3, 4]。
  • 配信ツリーの種類:
    • 最短パスツリー (SPT / Source Tree): 送信元をルート（根）とするツリー。表記は (S, G) [5]。
    • 共有ツリー (Shared Tree / Root-Path Tree): RPをルートとするツリー。表記は (*, G) [6]。

2. PIM Dense Mode (PIM-DM)

「ネットワーク上の全サブネットに受信者がいる」と想定し、最初に全ポートへトラフィックを転送（Flood）したあと、不要な経路を削る方式です [7, 8]。

  • Prune（プルーニング）: 下位に受信者がいない場合、上位ルーターに「送るのを止めてくれ」とメッセージを送り、ツリーからその枝を削除します [9, 10]。
  • State Refresh: Prune状態を維持するためのメッセージ。これが途切れると3分後に再びFloodが発生します [11, 12]。
  • Graft（グラフト）: 新たに受信者が現れた際、Prune状態のリンクを即座に復旧させるために使用します [13, 14]。

3. PIM Sparse Mode (PIM-SM)

「明示的な要求がない限り転送しない」方式です。トラフィックの集約点となる RP (Rendezvous Point) が不可欠です [15, 16]。

  • ソースの登録プロセス: 送信元に近いルーターがパケットをユニキャスト（Registerメッセージ）でRPにカプセル化して送り、登録を行います [17, 18]。
  • SPTスイッチオーバー: デフォルトでは、最初のパケットを共有ツリー（RP経由）で受け取った後、受信側ルーターは送信元へのより効率的な最短パス（SPT）へ自動的に切り替えます [19, 20]。

4. RP（Rendezvous Point）の選定と冗長化

PIM-SMにおいて、ルーターがどのRPを使用するかを決定する方法は主に4つあります [21]。

方法特徴
スタティックRP各ルーターに手動でRPのIPアドレスを設定 [22]。
Auto-RPCisco独自。Mapping AgentがRP情報を224.0.1.40で広報 [23, 24]。
BSR (Bootstrap Router)標準規格。BSRメッセージを全PIMルーターへフラッディング [25, 26]。
Anycast RP複数のRPに同一IPを付与し、IGPで最短のRPへルーティング。MSDPと併用 [27, 28]。

5. 高度なトピック

  • MSDP (Multicast Source Discovery Protocol): 異なるPIMドメインのRP間で送信元情報を共有するためのプロトコル。TCP 639番ポートを使用します [29, 30]。
  • SSM (Source-Specific Multicast): 受信者が特定のソースとグループのペア (S, G) を指定して参加する方式。RPが不要になり、アドレスの重複問題も解消されます [31, 32]。
  • Bidirectional PIM: 多数の送信元と受信者がいる環境で、RPへの登録プロセスを簡略化し、スケーラビリティを向上させます [26, 33]。

基本設定コマンド例

! PIM Sparse Mode の基本設定
ip multicast-routing
ip pim rp-address 10.1.10.3  ! スタティックRPの設定 [34]

interface GigabitEthernet0/1
 ip pim sparse-mode  ! インターフェースでの有効化 [35]

! Auto-RP Mapping Agent の設定
ip pim send-rp-discovery Loopback0 scope 16 [36]

! MSDP ピアの設定
ip msdp peer 172.16.1.1 [37]

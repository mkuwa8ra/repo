Chapter 19: Multiprotocol Label Switching

MPLSは、宛先IPアドレスではなく「ラベル」に基づいてパケットを転送する技術です。これにより、トラフィックエンジニアリング、QoS、VPNなどの高度なサービスを効率的に提供できます [1]。

1. MPLS ユニキャスト IP 転送

1.1 データプレーン：FIB と LFIB

MPLSルーター（LSR: Label Switch Router）は、パケットの状態に応じて2つの転送テーブルを使い分けます [1]。

  • FIB (Forwarding Information Base): ラベルのないパケットを受信した際に使用します。宛先IPに基づき、ラベルを付与（Push）して転送します [1]。
  • LFIB (Label Forwarding Information Base): ラベル付きパケットを受信した際に使用します。ラベルの付け替え（Swap）や除去（Pop）を行います [1]。

1.2 MPLS ヘッダーと TTL

  • ヘッダー構造: 20ビットのラベル、3ビットのEXP（QoS用）、1ビットのS（スタックの底を示す）、8ビットのTTLで構成されます [1]。
  • TTL 伝播: デフォルトではIPのTTLがMPLSラベルにコピーされます。これを無効にすると、MPLS内部のルーターが traceroute で隠蔽されます [1]。

1.3 コントロールプレーン：LDP

LDP (Label Distribution Protocol) は、ルーター間で「どのIPプレフィックスにどのラベルを割り当てたか」を共有します [2]。

  • LIB (Label Information Base): LDPで学習したすべてのラベル情報を保持するデータベースです。ここから最適な経路がLFIBへ反映されます [2]。

2. MPLS VPN

MPLS VPNは、サービスプロバイダーのネットワーク上で顧客ごとに独立したルーティング環境を提供します。複数の顧客が同じプライベートIP（10.0.0.0など）を使用していても、衝突することなく通信可能です [2]。

2.1 主要なコンポーネント

  • VRF (Virtual Routing and Forwarding): ルーター内部で顧客ごとに独立した仮想的なルーティングテーブルです [2]。
  • RD (Route Distinguisher): 重複するIPv4アドレスをグローバルでユニークな VPNv4アドレス（64bit RD + 32bit IPv4）に変換するための識別子です [2]。
  • RT (Route Target): どのVRFにどのルートをインポート/エクスポートするかを制御するBGP拡張コミュニティ属性です [2]。

2.2 データプレーン：2つのラベル

MPLS VPNではパケットに2層のラベルをスタックします [3]。

  • 外側ラベル (IGPラベル): 宛先側のPEルーターまでパケットを届けるために使用されます [3]。
  • 内側ラベル (VPNラベル): 宛先PEにおいて、どのVRF（顧客）へパケットを渡すべきかを識別するために使用されます [3]。
  • PHP (Penultimate Hop Popping): 宛先PEの負荷を軽減するため、その1つ手前のルーターで外側ラベルを除去する機能です [3]。

3. VRF Lite (Multi-VRF CE)

MPLSそのものを使用せずに、ルーター内で複数のVRFを構成してルーティングテーブルを分離する技術です。企業内でのネットワーク分離などに利用されます [3]。

基本設定コマンド例

! MPLS転送の有効化
ip cef
mpls ip
mpls label protocol ldp

! VRFの作成と設定
ip vrf Cust-A
 rd 1:111
 route-target export 1:100
 route-target import 1:100

! インターフェースへの適用
interface GigabitEthernet0/1
 ip vrf forwarding Cust-A
 ip address 192.168.1.1 255.255.255.0

! MP-BGPの設定（PEルーター間）
router bgp 65001
 neighbor 2.2.2.2 remote-as 65001
 address-family vpnv4
  neighbor 2.2.2.2 activate
  neighbor 2.2.2.2 send-community extended

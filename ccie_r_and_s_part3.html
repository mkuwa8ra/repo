Chapter 6: IP Forwarding (Routing)

IP転送（ルーティング）は、パケットを受信し、次に送る場所を決定して転送するプロセスです [1]。これは「データプレーン」と呼ばれ、実際のユーザーデータの転送を扱います [2]。

1. IP転送のロジックとスイッチングパス

ルーター内部でのパケット処理には、主に以下の3つの方式（スイッチングパス）があります [3-5]。

  • プロセススイッチング: CPUがすべてのパケットを処理する最も低速な方式です [6]。
  • ファストスイッチング: 最初のパケットのみプロセススイッチングし、結果をキャッシュに保存して以降のパケットを高速化します [4]。
  • Cisco Express Forwarding (CEF): トポロジ変更時にあらかじめ転送テーブルを構築しておく最も効率的な方式です。現在のCiscoルーターのデフォルトです [5, 7]。

CEFの主要なテーブル:

  • FIB (Forwarding Information Base): ルーティングテーブルに基づいて構築される転送用テーブル。mtrieという特殊な構造で高速検索を可能にします [7]。
  • Adjacency Table (隣接テーブル): FIBエントリから参照され、転送に必要なレイヤ2ヘッダー情報（MACアドレスなど）を保持します [7, 8]。

2. クラスレスルーティング vs クラスフルルーティング

ルーティングの判断は ip classless コマンドによって制御されます [9]。

  • ip classless (デフォルト): 宛先への最適なルートがない場合、デフォルトルートを使用して転送します [10]。
  • no ip classless: 宛先のクラスフルネットワークがルーティングテーブルにあるが、特定のサブネットへのルートがない場合、デフォルトルートを無視してパケットを破棄します [10]。

3. マルチレイヤスイッチング (MLS)

スイッチがレイヤ3の宛先アドレスに基づいて転送を判断することを指します [9]。

  • SVI (Switched Virtual Interface): VLANにIPアドレスを付与した仮想インターフェース [11]。
  • ルーテッドポート: no switchport コマンドでレイヤ2機能を無効にし、IPアドレスを直接設定した物理ポート [12, 13]。

4. ポリシーベースルーティング (PBR)

宛先IPアドレスだけでなく、送信元アドレスやプロトコル、パケットサイズなどに基づいて転送先を決定する機能です [14]。

  • ip policy route-map コマンドをインターフェースに適用します [14]。
  • 主な set コマンド:
    • set ip next-hop: 指定したネクストホップへ転送 [15]。
    • set ip default next-hop: ルーティングテーブルに一致するルートがない場合のみ適用 [15, 16]。

5. Performance Routing (PfR) / OER

ネットワークの遅延やジッター、パケット損失などの実際のパフォーマンスに基づいて最適なパスを選択する技術です [17, 18]。

  • Master Controller (MC): ポリシーを管理し、判断を下すルーター [19, 20]。
  • Border Router (BR): 実際のトラフィックを監視・制御し、MCと通信するルーター [20]。
  • パッシブモニタリング（NetFlow）とアクティブモニタリング（IP SLA）の両方をサポートします [18]。

6. GREトンネル

異なるネットワーク間でIPv6やCLNSなどのトラフィックをIPv4ネットワーク越しにカプセル化して運ぶ技術です [21, 22]。

基本設定・確認コマンド例

! CEFの有効化
ip cef

! ルーテッドポートの設定
interface gigabitethernet 0/1
 no switchport
 ip address 10.1.1.1 255.255.255.0

! PBRの設定
access-list 101 permit tcp any any eq telnet
route-map PBR_MAP permit 10
 match ip address 101
 set ip next-hop 192.168.1.1
interface fa0/0
 ip policy route-map PBR_MAP

! CEFの確認
show ip cef
show adjacency

Chapter 7: EIGRP

EIGRP (Enhanced Interior Gateway Routing Protocol) は、Cisco独自の拡張ディスタンスベクタプロトコルであり、高速な収束（Convergence）を実現するために DUAL (Diffusing Update Algorithm) を使用します [1, 2]。

1. EIGRPの基本動作と隣接関係

EIGRPは、トランスポート層プロトコルとして IPプロトコル番号 88 を直接使用します [3]。

  • 隣接関係（Adjacency）の確立条件: [4]
    • 認証（Authentication）の設定が一致していること。
    • AS番号（Autonomous System Number）が一致していること。
    • Helloパケットの送信元IPが、受信インターフェースのプライマリサブネット内にあること。
    • K値（K-values）が一致していること。
  • Hello/Holdタイマー: デフォルトはLANで5秒/15秒、低速なWANで60秒/180秒です [5]。なお、OSPFとは異なり、Hello/Holdタイマーが一致しなくても隣接関係を確立できます [5]。
  • RTP (Reliable Transport Protocol): Update、Query、Replyメッセージの確実な配信を保証するために使用されます [6, 7]。

2. メトリックの計算とトポロジテーブル

デフォルトでは 帯域幅（Bandwidth） と 遅延（Delay） を使用して計算されます [8, 9]。公式は 256 * ((10^7 / 最小帯域幅) + 合計遅延) です [10]。

  • Successor (サクセサ): 宛先への最適なルート [11]。
  • Feasible Successor (フィージブルサクセサ): バックアップルート。フィージビリティ条件（Feasibility Condition）を満たす必要があります [12, 13]。
  • FD (Feasible Distance): 自ルーターから宛先までの最小メトリック（サクセサのメトリック） [11]。
  • RD (Reported Distance): 隣接ルーターが通知してきた、そのルーターから宛先までのメトリック [12, 14]。
  • フィージビリティ条件: 「RD < 現在のFD」であること。これにより、バックアップパスがループフリーであることが保証されます [12]。

3. 収束（Convergence）とクエリ

サクセサルートが消失し、フィージブルサクセサが存在しない場合、ルートの状態は Passive から Active に変化します [15, 16]。

  • クエリ（Query）: 隣接ルーターに対して代替パスの有無を問い合わせるマルチキャストメッセージです [15, 17]。
  • Stuck-in-Active (SIA): クエリに対する応答（Reply）が一定時間内に返ってこない状態。この場合、応答のない隣接関係がリセットされます [2]。
  • クエリ範囲の限定: [18, 19]
    • ルート集約 (Summarization): 集約ルートを持つルーターがクエリに対して即座に応答することで、それ以上の拡散を防ぎます。
    • EIGRPスタブ (Stub): スタブルータにはクエリが送信されなくなります。

4. 高度な機能と設定

  • 不等コストロードバランシング: variance [値] コマンドを使用します [20]。フィージブルサクセサのみがルーティングテーブルに追加される点に注意してください [21]。
  • 認証: MD5 のみをサポートしています（クリアテキスト認証は不可） [22]。設定には key chain を使用します [23]。
  • Passive-interface: 設定したインターフェースでのHelloの送受信を停止し、隣接関係の確立を防ぎますが、そのサブネット自体は広報されます [24]。

基本設定コマンド例

! EIGRPの起動とAS番号の設定
router eigrp 1
 network 172.16.0.0 0.0.255.255
 no auto-summary

! スタブの設定（接続ルートと集約ルートのみ広報）
 eigrp stub connected summary

! 不等コストロードバランシングの設定
 variance 2

! インターフェース単位のメトリック調整
interface fastethernet 0/0
 delay 10  ! 単位は10マイクロ秒

Chapter 8: OSPF

OSPF (Open Shortest Path First) は、リンクステートルーティングプロトコルであり、ネットワークのトポロジ情報を正確に把握して最短パスを計算します [1, 2]。

1. OSPF データベース交換のプロセス

OSPFルーターは、以下の手順で隣接関係を築き、リンクステートデータベース (LSDB) を同期させます [3]。

  • ルーターID (RID) の選定: 32ビットの識別子。1. 手動設定、2. ループバックの最高IP、3. 物理インターフェースの最高IPの順で決定されます [4, 5]。
  • Hello プロセス: ネイバーの発見と維持に使用されます。Helloインターバル（デフォルト10秒/30秒）とDeadインターバル（デフォルト4倍）が一致する必要があります [6, 7]。
  • DR/BDRの選定: マルチアクセスネットワーク（イーサネットなど）では、LSAの交換を効率化するために 代表ルーター (DR) と バックアップ代表ルーター (BDR) が選出されます [8, 9]。
    • 優先度（Priority）が最も高いルーターがDRになります。タイの場合はRIDが比較されます [10]。
  • 状態遷移: Down → Init → 2-Way (ネイバー成立) → ExStart → Exchange → Loading → Full (完全隣接) [11, 12]。

2. OSPF ネットワークタイプ

インターフェースのメディアに応じて動作が異なります [13, 14]。

ネットワークタイプDR/BDR選定Hello/Deadネイバー設定
Broadcastあり10 / 40不要
Point-to-Pointなし10 / 40不要
Non-broadcast (NBMA)あり30 / 120必要 (static)
Point-to-Multipointなし30 / 120不要

3. LSA タイプとエリア設計

OSPFはLSA (Link State Advertisement) を使用して情報を広報します。エリア設計によって、どのLSAが流れるかが決まります [15, 16]。

  • Type 1 (Router LSA): すべてのルーターが自身のリンク情報をエリア内に生成します [16, 17]。
  • Type 2 (Network LSA): DRがマルチアクセスセグメントの情報をエリア内に生成します [16, 18]。
  • Type 3 (Summary LSA): エリア境界ルーター (ABR) が他のエリアのルート情報を要約して伝播します [16, 19]。
  • Type 4 (ASBR Summary LSA): ASBRまでのパスを他エリアへ通知します [20, 21]。
  • Type 5 (AS External LSA): AS境界ルーター (ASBR) が外部から再配送されたルートを広報します [20, 21]。
  • Type 7 (NSSA External LSA): NSSAエリア内で外部ルートを広報するために使用されます [20, 22]。

4. スタブエリアの種類

エリア内のLSDBのサイズを抑制するために使用されます [23, 24]。

エリアタイプType 5 阻止Type 3 阻止再配送 (Type 7)

NSSAYesNoYes
Totally NSSAYesYesYes

5. メトリック計算と特殊機能

  • コスト計算: デフォルトでは 10^8 / 帯域幅(bps) です [25, 26]。100Mbps以上のリンクを区別するためには auto-cost reference-bandwidth で基準値を変更する必要があります [25, 26]。
  • 仮想リンク (Virtual Link): エリア0に直接接続できないエリアをバックボーンに論理接続します。Transitエリアを通過しますが、スタブエリアを通過させることはできません [27, 28]。
  • 認証: タイプ0 (なし)、タイプ1 (クリアテキスト)、タイプ2 (MD5) をサポートします [29]。

基本設定コマンド例

! OSPFの起動とルーターIDの設定
router ospf 1
 router-id 1.1.1.1
 network 10.1.1.0 0.0.0.255 area 0
 network 10.2.1.0 0.0.0.255 area 1

! 参照帯域幅の変更 (10Gbps基準)
 auto-cost reference-bandwidth 10000

! 完全スタブエリアの設定 (ABR側)
 area 1 stub no-summary

! インターフェースでのコスト設定
interface fastethernet 0/0
 ip ospf cost 10

! 仮想リンクの設定 (ABR間)
router ospf 1
 area 1 virtual-link 2.2.2.2  ! 相手のRIDを指定

Chapter 9: IGP Route Redistribution, Route Summarization, Default Routing, and Troubleshooting

この章では、複数のIGP（内部ゲートウェイプロトコル）を併用する際に不可欠な再配送（Redistribution）、ルート集約、デフォルトルーティング、および複雑なレイヤ3のトラブルシューティングについて学びます [1]。

1. ルート制御のツール：Route Map と Prefix List

再配送の際には、特定のルートのみを許可したり、属性を変更したりするためのツールが必要になります [2]。

  • Route Map: matchコマンドで条件を指定し、setコマンドでメトリックやタグなどの属性を変更します [2, 3]。末尾には「暗黙の拒否（deny all）」が存在するため、許可しないルートを最後にパスさせるには明示的なpermit節が必要です [4]。
  • IP Prefix List: プレフィックス（ネットワークアドレス）とその長さ（サブネットマスク）の両方を効率的に照合できます [5, 6]。ge（〜以上）やle（〜以下）を使用することで、柔軟な範囲指定が可能です [6, 7]。

2. ルート再配送 (Route Redistribution)

あるルーティングプロトコルの情報を別のプロトコルへ注入するプロセスです [8]。

  • 基本ロジック: 再配送を行うルーターは、自身のルーティングテーブルにあるルート、またはnetworkコマンドで一致した接続サブネットを対象とします [9]。
  • シードメトリック (Seed Metric): プロトコルごとにメトリックの単位が異なるため、再配送時には初期メトリックの設定が必要です [10]。
    • RIP/EIGRP: デフォルトでは無限大（到達不能）となるため、明示的な設定が必須です [10]。
    • OSPF: 他のIGPからはデフォルトで20、BGPからは1が割り当てられます [10, 11]。
  • アドミニストレーティブディスタンス (AD): 複数のプロトコルから同じルートを学習した場合、AD値が低い方が優先されます（Connected: 0, EIGRP: 90, OSPF: 110, RIP: 120 など） [12, 13]。

3. ルート集約 (Route Summarization)

複数の個別ルートを1つの大きなプレフィックスにまとめ、ルーティングテーブルのサイズを削減します [14, 15]。

  • 集約ルートのメトリックは、通常、構成するサブネットの中で最小のものが採用されます [15]。
  • Null0 へのルーティング: ループ防止のため、集約を行うルーター自身には集約ルートを宛先とする Null0 へのルートが自動作成されます [15, 16]。

4. デフォルトルートの広報

各プロトコルでデフォルトルート（0.0.0.0/0）を広報する方法は異なります [17]。

プロトコル主な方法
RIPdefault-information originate、redistribute static、ip default-network [17, 18]
EIGRPredistribute static、ip default-network、ルート集約 [17, 19, 20]
OSPFdefault-information originate（alwaysオプションで自身のテーブルに無くても広報可能） [17, 21, 22]

5. レイヤ3 トラブルシューティング

複雑なルーティングの問題を解決するには、体系的なアプローチと適切なコマンドの知識が求められます [23]。

  • 確認コマンド:
    • show ip protocols: 動作中のプロトコル設定、フィルタ、AD値などを確認 [24]。
    • show ip route [prefix]: 特定のルートのネクストホップや学習ソースの詳細を表示 [25]。
    • debug ip routing: ルーティングテーブルへの追加・削除をリアルタイムで追跡 [26, 27]。
  • ループの検知: pingやtracerouteでの異常な挙動や、debugでの頻繁なルートの学習と削除（フラッピング）が最初の手がかりになります [28, 29]。

基本設定コマンド例

! OSPFへの再配送（サブネットを含む）
router ospf 1
 redistribute eigrp 100 subnets metric 50

! EIGRPへの再配送とシードメトリックの設定
router eigrp 100
 redistribute ospf 1 metric 10000 100 255 1 1500

! OSPFでのデフォルトルート強制広報
router ospf 1
 default-information originate always

! 特定のルートのみを再配送するRoute Map
access-list 10 permit 10.1.1.0 0.0.0.255
route-map MY_FILTER permit 10
 match ip address 10
 set metric 100

Chapter 10: Fundamentals of BGP Operations

BGP (Border Gateway Protocol) はインターネットの基盤となるパスベクタプロトコルであり、自律システム (AS) 間でルーティング情報を交換するために使用されます。本章では、ネイバー関係の構築、BGPテーブルへのルート注入、およびiBGPの制約を克服する技術について学びます。

1. BGP ネイバー関係の構築

BGPはトランスポート層に TCP ポート 179 を使用して信頼性の高い通信を行います [1]。ネイバー状態が Established に達して初めてルートの更新（Update）が可能になります [2, 3]。

  • iBGP (Internal BGP): 同一AS内のルーター間でのピアリング [4]。
    • デフォルトでは、iBGPで学習したルートを他のiBGPピアへ転送しません（スプリットホライズン）。これを解決するにはフルメッシュ構成、ルートリフレクタ、またはコンフェデレーションが必要です [5, 6]。
  • eBGP (External BGP): 異なるAS間のルーター間でのピアリング [4]。
    • デフォルトの TTL は 1 です。ループバックアドレスでピアリングを行う場合は ebgp-multihop 設定が必要です [7]。
  • 主要なメッセージタイプ: Open（開始）、Keepalive（維持）、Update（更新）、Notification（エラー通知） [8, 9]。

2. BGP テーブルへのルート注入

BGPテーブルにルートを入れるには、主に以下の方法があります。

  • network コマンド: IPルーティングテーブル（RIB）に 完全に一致するプレフィックスとマスク のルートが存在する場合のみ、BGPテーブルに注入されます [10, 11]。
  • Redistribution (再配送): IGPやスタティックルートをBGPに注入します。ORIGIN属性は Incomplete (?) となります [12-14]。
  • aggregate-address コマンド: 手動のルート集約を行います。as-set オプションを使用すると、集約前のルートに含まれていたAS番号情報を保持し、ループを防止できます [15-17]。

3. パス属性 (Path Attributes)

BGPはメトリックの代わりに複数の属性を使用してベストパスを決定します [18]。

  • AS_PATH: ルートが通過したAS番号のリスト。ループ検知に使用され、自AS番号が含まれるアップデートは破棄されます [19, 20]。
  • NEXT_HOP: 宛先へ到達するためのネクストホップIP。eBGPピアへ送る際は自身のIPに変更されますが、iBGPピアへ送る際はデフォルトで 変更されません（必要に応じて next-hop-self を使用します） [21-23]。
  • ORIGIN: ルートの起源。IGP (i)、EGP (e)、Incomplete (?) の3種類があります [13, 24]。

4. スケーラビリティ：ルートリフレクタとコンフェデレーション

iBGPのフルメッシュ要件（ピア数 N*(N-1)/2）による負荷を軽減するための技術です [6]。

  • ルートリフレクタ (Route Reflector): 特定のルーター（RR）がクライアントから受け取ったルートを他のピアに「反射」することを許可します [25, 26]。
    • ループ防止のため CLUSTER_LIST と ORIGINATOR_ID 属性を使用します [27]。
  • コンフェデレーション (Confederation): 1つの大きなASを小さなサブASに分割します [28, 29]。
    • 外部からは1つのASとして見えますが、内部では eBGPに近い動作（AS_CONFED_SEQの使用）をします [20, 30, 31]。
  • 同期 (Synchronization): IGPがそのルートを知るまでBGPルートを有効にしない古いルール。現在は no synchronization が一般的です [32]。

基本設定コマンド例

! 基本的なBGP設定とネイバー
router bgp 123
 neighbor 1.1.1.1 remote-as 123
 neighbor 1.1.1.1 update-source Loopback0
 neighbor 1.1.1.1 next-hop-self
 !
 address-family vpnv4
  neighbor 1.1.1.1 activate
  neighbor 1.1.1.1 send-community
 exit-address-family

! ルート集約（AS_SET情報を含む）
 aggregate-address 10.0.0.0 255.0.0.0 as-set summary-only

! ルートリフレクタの設定（サーバ側）
 neighbor 2.2.2.2 route-reflector-client

Chapter 11: BGP Routing Policies

BGPルーティングポリシーは、ルートのフィルタリングと、どのルートを「ベストパス」として選択するかを制御するためのルールを定義します [1]。本章では、フィルタリングツール、AS_PATHの正規表現、BGPベストパス決定プロセス、およびコミュニティ属性について詳細に学びます。

1. ルートフィルタリングツール

BGPアップデートは、NLRI（ネットワーク情報）またはパス属性に基づいてフィルタリングできます [2]。

  • NLRIフィルタリング: 分配リスト（ACLを使用）、プレフィックスリスト、ルートマップを使用して、特定のネットワークプレフィックスを許可または拒否します [3, 4]。
  • AS_PATHフィルタリング: 正規表現 (Regular Expressions) を使用してAS_PATH属性の内容を照合します [5, 6]。ip as-path access-listコマンドで定義し、neighbor filter-listで適用します [7, 8]。
  • ソフト再構成 (Soft Reconfiguration): ネイバー接続をリセットせずにルーティングポリシーを再適用する機能です [9]。clear ip bgp [address] softコマンドを使用します [9]。

2. AS_PATHの正規表現 (Regex)

AS_PATHフィルタでは特殊な文字（メタキャラクタ）を使用してパターンをマッチングさせます [10]。

メタキャラクタ意味
^行の先頭（最初のAS番号など）[10]
$行の末尾 [10]
_任意の区切り文字（スペース、カンマ、先頭、末尾など）[10]
.*すべてのAS_PATH（「すべて許可」によく使われる）[11]
^$空のAS_PATH（自AS内で生成されたルート）[12]

3. BGPベストパス決定プロセス

BGPは、複数の候補ルートがある場合、以下の優先順位に従って1つのベストパスを決定します [13, 14]。

  1. NEXT_HOPの到達性: ネクストホップIPアドレスがルーティングテーブル上で到達可能であること [15, 16]。
  2. Weight: Cisco独自属性。値が大きい方を優先（ルーター内のみ有効）[15, 17]。
  3. LOCAL_PREF: AS全体で共有される優先度。値が大きい方を優先 [18, 19]。
  4. ローカル注入ルート: 自身で注入したルート（networkやredistribute）を優先 [20, 21]。
  5. AS_PATH長: AS番号のリストが短い方を優先 [21, 22]。
  6. ORIGIN PA: IGP(i) > EGP(e) > Incomplete(?) の順で優先 [23, 24]。
  7. MED (Multi-Exit Discriminator): 隣接ASへの出口を指定。値が小さい方を優先 [23, 25]。
  8. ネイバータイプ: iBGPよりeBGP経由のルートを優先 [14, 26]。
  9. IGPメトリック: NEXT_HOPへのIGPメトリックが最小のパスを優先 [26, 27]。
  10. BGP Router ID / Neighbor ID: 最終的なタイブレーカーとして、最小のRIDを持つルーターからのルートを選択 [28-30]。

4. BGPコミュニティ属性

ルートをグループ化し、ポリシーを適用しやすくするための属性です [31]。コミュニティ属性は、遠隔のASにあるルーターにポリシー情報を伝える強力な手段となります [31]。

  • Well-knownコミュニティ:
    • NO_EXPORT: 外部AS（eBGPピア）にルートを広報しない [32]。
    • NO_ADVERTISE: 他のどのBGPピアにもルートを広報しない [33]。
    • LOCAL_AS: コンフェデレーション外に広報しない [33]。
  • 設定: ルートマップのset communityコマンドで値を付与し、neighbor send-communityコマンドで属性を送信します [34, 35]。

基本設定・確認コマンド例

! AS_PATHフィルタの設定（AS 1から始まり、AS 44で終わるパスを拒否）
ip as-path access-list 34 deny ^1_.*_44$
ip as-path access-list 34 permit .*
router bgp 123
 neighbor 10.1.34.3 filter-list 34 out

! LOCAL_PREFを200に設定するルートマップ
route-map SET_LP permit 10
 match ip address prefix-list MY_NET
 set local-preference 200

! コミュニティ属性の付与と送信
router bgp 123
 neighbor 10.1.1.1 route-map SEND_COMM out
 neighbor 10.1.1.1 send-community
route-map SEND_COMM permit 10
 set community no-export

! ベストパス選択の詳細確認
show ip bgp [prefix]

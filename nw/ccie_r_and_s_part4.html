Chapter 12: Classification and Marking

分類とマーキングの目的は、複雑な識別プロセスを一度だけ行い、パケットに特定の値をマークすることで、後続のQoSツールがそのマークを見るだけで迅速に処理を決定できるようにすることです[1]。

1. QoSマーキングに使用されるフィールド

IPヘッダーやレイヤ2ヘッダーには、QoS用にマーク可能なフィールドがいくつか存在します[2]。

  • IP Precedence (IPP): IPヘッダーのToSバイトの上位3ビットを使用します[2, 3]。
  • DSCP (Differentiated Services Code Point): ToSバイトを再定義した「DSフィールド」の上位6ビットを使用し、よりきめ細かなサービスレベルを定義できます[3, 4]。
  • Class Selector (CS): IPPとの後方互換性を保つためのDSCP値のセットです[5, 6]。
  • Assured Forwarding (AF): 4つのクラスと3段階の破棄優先度を定義する12個のDSCP値です（例：AF41）[7, 8]。
  • Expedited Forwarding (EF): 低遅延が求められるトラフィック（VoIPなど）向けのDSCP値（101110 / 10進数46）です[4, 8]。
  • CoS (Class of Service): 802.1QやISLなどのトランクヘッダーに含まれる3ビットのフィールドです[9, 10]。

2. Cisco Modular QoS CLI (MQC)

CiscoはQoS設定を統合し簡素化するために、MQCを導入しました[11, 12]。以下の3つの主要な要素で構成されます。

  • Class Map (class-map): トラフィックを分類するための条件を定義します[13, 14]。
  • Policy Map (policy-map): 分類されたクラスに対して実行するQoSアクション（マーキングやキューイングなど）を定義します[13, 15]。
  • Service Policy (service-policy): ポリシーマップをインターフェースの入力または出力に適用します[13, 15]。

3. NBAR (Network-Based Application Recognition)

NBARは、動的なポート番号を使用するアプリケーションや、HTTPのURL、ホスト名などの深いパケットインスペクションを必要とする分類に使用されます[16, 17]。MQCの match protocol コマンドを使用することで、NBARによる識別が有効になります[17, 18]。

4. 高度なマーキング機能

  • QoS Pre-classification: VPNトンネル（GREやIPsec）で暗号化される前の元のパケットヘッダーをメモリに保持し、カプセル化後の出力インターフェースで適切なQoS処理を行えるようにする機能です[19, 20]。
  • Policy Routing (PBR) によるマーキング: 宛先IPアドレス以外の情報に基づいてルートを変更すると同時に、IPPやToSバイト全体をマークすることも可能です[21, 22]。

5. Cisco AutoQoS

Ciscoのベストプラクティスに基づいたQoS設定を自動生成するマクロです[23]。設定ミスを減らし、導入を高速化できます[23]。VoIP用（AutoQoS for VoIP）とエンタープライズ用（AutoQoS for the Enterprise）の2種類があります[24, 25]。

基本設定コマンド例

! Class Map の定義（URLに"important"を含むHTTPを識別）
class-map http-important
 match protocol http url "*important*"

! Policy Map の定義（識別したトラフィックをAF21にマーキング）
policy-map QoS-POLICY
 class http-important
  set ip dscp af21
 class class-default
  set ip dscp default

! インターフェースへの適用（入力パケットに対して実行）
interface GigabitEthernet0/1
 service-policy input QoS-POLICY

Chapter 13: Congestion Management and Avoidance

輻輳管理（キューイング）は、デバイスから送信されるのを待機しているパケットをどのように管理するかを定義します [1]。本章では、ルーターにおけるCBWFQやLLQ、スイッチにおけるSRR、そして輻輳回避技術であるWREDについて学びます。

1. Cisco ルーターのキューイング概念

ルーターには、物理的な送出の直前に位置するハードウェアキュー（TXリング）と、その手前でパケットを整理するソフトウェアキューの2段階が存在します [2, 3]。

  • ハードウェアキュー: 常にFIFO（先入れ先出し）で動作します。このキューを短く設定することで、ソフトウェアキューによる優先制御をより迅速に反映させることができます [2, 3]。
  • ソフトウェアキュー: ネットワーク管理者がQoSツール（CBWFQなど）を適用する場所です。インターフェースが輻輳したときにのみアクティブになります [2, 4]。

2. CBWFQ と LLQ

現代のCiscoルーターで最も一般的に使用されるキューイングツールです。

  • CBWFQ (Class-Based Weighted Fair Queuing):
    • MQCを使用して最大64のクラスを定義できます [5, 6]。
    • 各クラスに対して、帯域幅の最小保証（bandwidthコマンド）を提供します [7, 8]。
  • LLQ (Low Latency Queuing):
    • CBWFQに厳格な優先順位（Strict Priority）キューを追加したものです [6, 9]。
    • priorityコマンドで指定されたクラスは、他のどのキューよりも先に処理されます。音声（VoIP）などの遅延に敏感なトラフィックに不可欠です [9, 10]。
    • 他のキューが枯渇（スタベーション）しないよう、優先クラスにはポリサーによる帯域制限が自動的に適用されます [6, 10]。

3. WRED (Weighted Random Early Detection)

キューが満杯になってからパケットを捨てる「テールドロップ」は、TCPのグローバル同期を引き起こし、ネットワーク効率を低下させます。これを回避するのがWREDです [11, 12]。

  • 動作原理: キューの平均的な深さを監視し、閾値を超えるとパケットをランダムに破棄し始めます [12-14]。
  • 重み付け: IP PrecedenceやDSCPの値に基づいて破棄の閾値を調整できます。重要度の高いパケットはより捨てられにくく設定します [15, 16]。

4. LANスイッチのキューイング (3560シリーズ)

スイッチのQoSはASICで行われるため、ルーターとは異なる独自の仕組みを持ちます [17, 18]。

  • SRR (Shaped Round Robin): キュー間での帯域共有方法を制御します [19, 20]。
    • 共有モード (Shared): 設定された比率で帯域を分配しますが、空き帯域があれば他のキューがそれを利用できます [20, 21]。
    • シェイピングモード (Shaped): キューが使用できる帯域に厳格な上限を設定します [20, 21]。
  • WTD (Weighted Tail Drop): スイッチにおけるテールドロップの拡張版で、CoSやDSCPの値に基づいてドロップ閾値を複数定義できます [17, 19, 22]。

5. RSVP (Resource Reservation Protocol)

受信側から送信側へ、ネットワーク上のパスに沿って明示的に帯域を予約するためのシグナリングプロトコルです [1, 23]。

  • フロー（宛先IP、ポート、プロトコル）単位でリソースを確保します [23]。
  • 予約が完了すると、パス上のルーターは各インターフェースでそのフローのための帯域を維持します [23, 24]。

基本設定コマンド例

! CBWFQ/LLQ の設定
policy-map MY-QoS
 class voice-class
  priority 64             ! LLQ: 64kbpsの優先帯域
 class critical-data
  bandwidth percent 30    ! CBWFQ: インターフェース帯域の30%を保証
 class class-default
  fair-queue              ! デフォルトクラスでWFQを有効化

! WRED の有効化 (CBWFQクラス内)
 class critical-data
  random-detect dscp-based

! RSVP の設定 (インターフェース)
interface Serial0/0
 ip rsvp bandwidth 128 64 ! 全体で128k、1フロー最大64kを予約可能にする

Chapter 14: Shaping, Policing, and Link Fragmentation

シェイピングとポリシングは、トラフィックの送信レートを制限するためのツールです。本章では、パケットを遅延させるシェイピング、パケットを破棄または再マークするポリシング、および低速リンクでの遅延を軽減する断片化（LFI）について学びます [1, 2]。

1. トラフィックシェイピングの概念

シェイピングは、設定されたレートを超えるトラフィックをバッファ（シェイピングキュー）に保持し、平滑化して送出します [1]。

  • 主要な用語 [1]:
    • Tc (Time Interval): データを送信する時間間隔（ミリ秒）。公式：Tc = Bc / シェイピングレート。
    • Bc (Committed Burst): 各Tcの開始時に送信可能なデータ量（ビット）。
    • Be (Excess Burst): アイドル期間の後に、Bcを超えて送信できる追加のデータ量。
    • CIR (Committed Information Rate): 契約上の基本帯域幅（bps）。
  • 動作の仕組み: トークンバケットアルゴリズムを使用します。各Tcの開始時にバケットへBcトークンが補充され、送信時にトークンを消費します [1, 2]。

2. シェイピングの種類と設定

  • Generic Traffic Shaping (GTS): インターフェース全体、またはACLで指定した特定のトラフィックをシェイピングします [2]。
  • Class-Based Shaping (CB Shaping): MQCを使用して特定のクラスごとにシェイピングを適用します。Ciscoが推奨する最新の手法です [2]。
    • shape average: 平均レートでのシェイピング。
    • shape peak: Bc + Beを利用したピークレートでのシェイピング [2]。
  • Frame Relay Traffic Shaping (FRTS): フレームリレーネットワーク固有のシェイピング。BECN（後方向輻輳通知）を受けてレートを動的に下げる「適応型シェイピング」をサポートします [2]。

3. ポリシング (Policing) の概念と構成

ポリシングは、トラフィックが契約レートを超えた瞬間に、パケットを即座に破棄するか、優先度を下げて再マーク（マークダウン）します。シェイピングとは異なり、パケットをバッファリングしません [2]。

  • CB Policing のカテゴリ [2, 3]:
    • Conforming (適合): 契約レート内。通常はそのまま転送。
    • Exceeding (超過): バースト許容範囲内だがレート超。再マークして転送、または破棄。
    • Violating (違反): 完全にレート超。通常は破棄。
  • ポリサーのタイプ [2]:
    • Single-Rate, Three-Color: 1つのレート（CIR）に基づき、Bc/Beバケットを使用して3色（適合/超過/違反）で判断。
    • Two-Rate, Three-Color: 2つのレート（CIRとPIR）に基づき、より厳格なバースト管理を行う。

4. リンク効率化ツール (LFI)

シリアルリンクなどの低速なWANリンクにおいて、大きなデータパケットによる音声パケットの遅延（シリアライゼーション遅延）を防ぐ技術です [4]。

  • FRF.12: フレームリレー用の断片化。大きなデータフレームを分割し、その間に音声フレームを割り込ませます [5]。
  • Multilink PPP (MLP) LFI: PPP環境での断片化。フラグメント間のインターリーブをサポートします [4]。

5. QoS のトラブルシューティング

QoSが期待通りに動作しない場合は、以下の手順で確認します [3]。

  • show policy-map interface: 各クラスでパケットが正しく分類され、ドロップが発生しているか、または設定通りにマークされているかを確認します [3]。
  • show ip nbar protocol-discovery: 特定のアプリケーション（CitrixやP2Pなど）が想定外のクラスに入っていないか、NBARの統計を確認します [3]。
  • show traffic-shape: 現在のシェイピングレート、Tc、バッファの状態を確認します [3]。

基本設定コマンド例

! CB Shaping の設定例
policy-map SHAPE-POLICY
 class class-default
  shape average 128000 1280 0  ! レート 128k, Bc 1280bit, Be 0
  service-policy LLQ-QUEUING   ! シェイピングキューにLLQを階層適用

! CB Policing の設定例
policy-map POLICE-POLICY
 class HTTP-TRAFFIC
  police cir 256000 bc 8000 be 8000
   conform-action transmit
   exceed-action set-dscp-transmit 0
   violate-action drop

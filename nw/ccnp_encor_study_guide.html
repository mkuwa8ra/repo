ハードウェア転送技術 — CEF / TCAM

パケットをどのように高速転送するか。コントロールプレーンとデータプレーンの分離。

転送方式の進化
CEF (Cisco Express Forwarding)
  • RIB→FIBルーティングテーブルをFIBに同期（ハードウェア転送用）
  • ARP→隣接ARPテーブルを隣接テーブル(Adj Table)に同期
  • 効果CPU介入なしでパケット転送。デフォルト有効。
TCAM (Ternary Content Addressable Memory)
  • 値0 / 1 / X（ワイルドカード）の3値で処理
  • 速度サブネットマスク一致を1クロックで判定
  • 用途ACL・ルートルックアップ・QoSマッチング
CEF データフロー

レイヤ2技術 — STP / EtherChannel

ループ防止と冗長化。現場での2大トラブルメーカーの1つ。

STP ポート状態遷移（PVST+）
STP ロール選出プロセス
1
ルートブリッジ選出

Bridge ID (Priority 32768 + VLAN + MAC) が最小のスイッチ。全ポートが Designated Port になる。

2
ルートポート決定

非ルートブリッジの各スイッチで、ルートブリッジへのコスト最小ポート。

3
指定ポート / 非指定ポート決定

各セグメントで1つを Designated、残りを Non-Designated（Blocking）にする。

4
PortFast 設定

PCやサーバー接続ポートに設定。即座に Forwarding へ。BPDUGuard と必ずセットで。

⚡
Rapid PVST+ (802.1w) — 収束時間を数秒に短縮。Proposal/Agreement メカニズムにより即時同期。現代の推奨設定。
STPコスト比較
帯域幅コスト (旧)コスト (新・推奨)
10 Mbps1002,000,000
100 Mbps19200,000
1 Gbps420,000
10 Gbps22,000
100 Gbps—200
EtherChannel (ポートチャネル)
LACP (標準 802.3ad)
  • モードactive / passive
  • 条件両端が active か、片端が active
  • 推奨マルチベンダー環境で利用
PAgP (Cisco独自)
  • モードdesirable / auto
  • 条件両端が desirable か、片端が desirable
  • 制限Ciscoデバイス間のみ
ロードバランシング
  • 単位パケット単位ではなくフロー単位
  • 最大帯域1端末は物理リンク1本分
  • ハッシュsrc/dst IP・MACなど複数方式
✅
EtherChannelはSTPから見て1本の論理リンクのため、STPのブロッキングが発生しない。障害時のダウンタイムも 1秒未満。

レイヤ3技術 — OSPF

標準リンクステート型プロトコル。エリア設計とDR/BDR選出が重要。

OSPFネイバー確立フロー
1
Down

Hello未受信の初期状態

2
Init

Hello受信。まだ自分のRIDは含まれていない

3
2-Way

双方のHelloに互いのRIDが含まれる。DR/BDR選出はここで

4
ExStart

マスター/スレーブを決定。DBD交換開始

5
Exchange

DBD（データベース概要）を交換

6
Loading

LSRequest → LSUpdate → LSAck

✓
Full ← 目標はここ！

LSDB同期完了。アジャセンシー確立

OSPF エリア設計
DR / BDR 選出とネットワークタイプ
DR / BDR 選出（マルチアクセスネットワーク）
  • DRPriority最大(デフォルト1) → 同値ならRouter-ID最大
  • BDRDR次点。DRダウン時に昇格
  • DROTHERDR/BDRとのみFull。他はFull不要
  • Priority 0DR/BDRに絶対なれない
ネットワークタイプ
タイプDR/BDR代表例
BroadcastありEthernet
Point-to-Pointなしシリアル/GRE
NBMAありFrame Relay
Point-to-MultipointなしHubSpokeなど
主要コマンド
! インターフェース単位でOSPF有効化（推奨） interface GigabitEthernet0/0 ip ospf 1 area 0 ! ルーターIDを明示的に設定（重複不可・必須推奨） router ospf 1 router-id 1.1.1.1 ! ネイバー確認 → STATEがFULLであることを確認 show ip ospf neighbor show ip ospf interface brief show ip route ospf
⚠️
OSPFアジャセンシーが張れない主な原因：Hello/Deadタイマー不一致、エリアID不一致、サブネットマスク不一致（ネットワークタイプによる）、認証設定の差異。

NAT / PAT — FHRP — HA技術

アドレス変換と冗長化。PATとHSRP/VRRPは現場の基本構成。

NAT の種類
Static NAT

プライベートIPとグローバルIPを1対1で対応。サーバー公開などに使用。

Dynamic NAT

アドレスプールから動的に割り当て。プール枯渇すると接続不可になる。

PAT (Overload) ← 現在の主流

多数のプライベートIPをポート番号で識別し、1つのグローバルIPに多重化。

FHRP 比較
プロトコル種別Active側呼称Standby側呼称マルチグループLB
HSRP v1/v2Cisco独自ActiveStandby可（MHSRP）
VRRP標準 (RFC)MasterBackup可
GLBPCisco独自AVGAVF（全台稼働）自動LB（全台Active）
SSO (Stateful Switchover)

スーパーバイザーを冗長化。アクティブ/スタンバイでステートを同期。切り替え時もセッション情報を保持。

NSF (Non-Stop Forwarding)

SSO切り替え中も転送を継続。隣接ルーターにGraceful Restartを通知し、ルーティング情報を保持してもらう。

05

マルチキャスト

グループメンバーにのみ効率的に配信。IGMP + PIM の組み合わせ。

マルチキャストアドレス体系
  • 範囲224.0.0.0 〜 239.255.255.255
  • リンクローカル224.0.0.0/24（ルーターが転送しない）
  • OSPF Hello224.0.0.5 / 224.0.0.6
  • HSRP224.0.0.2
  • PIM224.0.0.13
  • グローバルスコープ224.0.1.0 〜 238.255.255.255
  • 管理用スコープ239.0.0.0/8（プライベート）
PIM モード比較
PIM Dense Mode (DM)

まずフラッドし、不要なルーターからPruneで剪定。密な環境向け。現在はほぼ非推奨。

PIM Sparse Mode (SM) ← 主流

RP（Rendezvous Point）を中心にツリーを構築。受信希望ルーターがJoinを送信。まばらな環境に最適。

! RP設定 ip pim rp-address 10.0.0.1 ! Auto-RP or BSR でRP自動配布も可
マルチキャスト関連プロトコル
IGMP (Internet Group Management Protocol)
  • 役割ホストとルーター間のグループ管理
  • v1基本的なJoin/Leave
  • v2Leave Group追加（高速離脱）
  • v3送信元フィルタリング対応
IGMP Snooping

L2スイッチがIGMPを監視し、マルチキャストをグループメンバーポートにのみ転送。フラッド防止に必須。

RPF (Reverse Path Forwarding)

送信元IPに対してルーティングテーブルを逆引きし、正しいインターフェースから来たパケットのみ転送。ループ防止。

仮想化技術 — VRF / GRE / IPsec

ネットワーク仮想化と安全なトンネリング。VRF・GRE・IPsecの連携。

サーバー仮想化
VRF (Virtual Routing and Forwarding)
GRE / IPsec トンネリング
GRE の特徴
  • プロトコルProtocol 47
  • マルチキャスト対応可（OSPF等も流せる）
  • 暗号化なし → IPsecと組み合わせ必須
IPsec の構成要素
  • IKE Phase1ISAKMP SAの確立（認証・鍵交換）
  • IKE Phase2IPsec SAの確立（データ保護）
  • ESP暗号化+認証（Protocol 50）
  • AH認証のみ（暗号化なし）
DMVPN / FlexVPN

Hub-and-Spoke構成を効率化するGREベースのソリューション。スポーク同士のダイナミックトンネルも確立可能。

07

SDN — SD-Access — SD-WAN

ネットワーク自動化とソフトウェア定義ネットワークのアーキテクチャ。

SDN アーキテクチャ レイヤー
SD-Access アーキテクチャ
  • VXLANL2フレームをUDPでカプセル化して転送（VNID 24bit）
  • LISPエンドポイントの位置（RLOC）とID（EID）を分離解決
  • SGTユーザー/デバイスにタグを付与してグループポリシー制御
  • IBNIntent-Based Networking：意図(Intent)を宣言するだけで自動設定
SD-WAN コンポーネント
1
vManage (Manager)

GUI管理ポータル。設定テンプレートの作成・配布。

2
vBond (Validator)

エッジデバイスの認証・オーケストレーション。NAT越えを支援。

3
vSmart (Controller)

OMPでルーティング情報・ポリシーをエッジに配布。

4
WAN Edge (cEdge / vEdge)

実際のデータ転送担当。MPLS/インターネット/LTEを使い分け。

OMP (Overlay Management Protocol)

SD-WANのコントロールプレーン。vSmartとエッジ間でルート・ポリシー・セキュリティ情報を交換。BGPライクな動作。

ネットワーク管理 / 監視

NTP・SNMP・Syslog・NetFlow・SPAN・IP SLA — 運用の基本ツール群。

NTP (Network Time Protocol)
  • ポートUDP 123
  • Stratum 0原子時計・GPS（参照源）
  • Stratum 1Stratum 0直結のNTPサーバー
  • Stratum 2+上位から時刻同期（最大15）
  • 重要性ログ・証明書・Kerberosに必須
SNMP (Simple Network Management Protocol)
  • 推奨v3 認証+暗号化
  • GETマネージャー→エージェントへ情報要求
  • SETマネージャー→エージェントへ設定変更
  • Trapエージェント→マネージャーへ自発通知
  • MIB管理情報ベース（OIDで識別）
Syslog
レベル名称
0Emergency（最重要）
1Alert
2Critical
3Error
4Warning
5Notice
6Informational
7Debugging（最低重要）
NetFlow / IPFIX
  • 目的フロー単位のトラフィック統計収集
  • v5固定フォーマット・IPv4のみ
  • v9テンプレートベース・柔軟
  • IPFIXNetFlow v9ベースの標準化版（RFC 7011）
  • フロー定義src/dst IP・ポート・プロトコル・ToS・入力IF
SPAN / RSPAN / ERSPAN
  • SPAN同じスイッチ内でポートミラーリング
  • RSPANリモートスイッチまでVLANで転送してキャプチャ
  • ERSPANGREカプセル化でネットワーク越しにキャプチャ
  • 用途Wiresharkでのパケット分析・IDS/IPS接続
IP SLA (Service Level Agreement)

テストパケット（ICMP Echo, UDP Jitter, HTTP, DNSなど）を定期送信し、遅延・ジッター・到達性を測定。

! IP SLA設定例 - ICMPエコーで疎通確認 ip sla 1 icmp-echo 8.8.8.8 source-interface GigabitEthernet0/0 frequency 30 ip sla schedule 1 life forever start-time now ! スタティックルートの切り替えに活用 ip route 0.0.0.0 0.0.0.0 203.0.113.1 10 track 1 ip route 0.0.0.0 0.0.0.0 198.51.100.1 20

セキュリティ / QoS

ACL・CoPP・NGFW・MACsec — そしてQoSの分類・マーキング・キューイング。

ACL の種類と適用
種類番号マッチ条件
Standard1-99 / 1300-1999送信元IPのみ
Extended100-199 / 2000-2699src/dst IP・ポート・プロトコル
Named Standard名前送信元IPのみ
Named Extended名前src/dst IP・ポート・プロトコル
⚠️
Standardは送信先に近い側、Extendedは送信元に近い側に適用するのが原則。末尾に暗黙のDenyが存在。
CoPP (Control Plane Policing)

コントロールプレーン（CPU）に向かうトラフィックをポリシングし、DoS攻撃から機器自体を守る。ACLで分類しポリシーマップで適用。

AAA フレームワーク
Authentication (認証)

「あなたは誰か」— ユーザー名・パスワード・証明書で本人確認。

Authorization (認可)

「何をしていいか」— 権限に応じてアクセス可能なリソース・コマンドを制御。

Accounting (アカウンティング)

「何をしたか」— 全操作を記録し監査証跡を残す。

プロトコルポート暗号化範囲特徴
RADIUSUDP 1812/1813パスワードのみ一般ユーザー認証に多用
TACACS+TCP 49全体管理者アクセス・コマンド認可に適す
QoS — 処理パイプライン
マーキング値
レイヤフィールド値範囲用途例
L2CoS (PCP)0-7 (3bit)802.1Qタグ
L3DSCP0-63 (6bit)EF=46(音声)、AF=優先データ
L3 (旧)IPP (TOS)0-7 (3bit)DSCPの上位3bitと互換
キューイング方式
  • FIFO単純な先着順。差別化なし。
  • WFQフロー単位で重み付け公平配分
  • CBWFQクラスごとに帯域保証（Policy Map）
  • LLQCBWFQ + 優先キュー（音声/ビデオ用）
  • PQ絶対優先。空になるまで他は待機。

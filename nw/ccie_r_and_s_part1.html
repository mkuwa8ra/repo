Chapter 1: Ethernet Basics

キャンパスネットワークのほとんどはイーサネット技術を使用して構築されています [1]。この章では、物理層からデータリンク層、スイッチングの基本論理までを扱います。

1. イーサネット・レイヤ1：配線、速度、デュプレックス

イーサネットLANを機能させるには、正しいケーブル配線が不可欠です [2]。

  • RJ-45ピン配列： PCなどのNICはピン1,2で送信し3,6で受信しますが、スイッチポートは逆に3,6で送信し1,2で受信します [3]。
  • ストレートケーブル： PCとスイッチのように、異なる送信ピンを持つデバイス同士を接続します [3]。
  • クロスケーブル： スイッチ同士やPC同士など、同じピンで送信を行うデバイス間で使用し、送信ペアと受信ペアを交差させます [3, 4]。
  • Auto-MDIX： 正しいケーブルタイプが使用されていない場合に、自動的に検知して送受信ペアを入れ替える機能です [5]。

オートネゴシエーションとデュプレックス [6]:

  • Ciscoスイッチはデフォルトでオートネゴシエーションを使用します [6]。
  • 全二重 (Full-duplex)： 衝突が発生しない環境（共有ハブを使用しない接続）で使用可能です [4, 7]。
  • 半二重 (Half-duplex)： デュプレックスの不一致が発生すると、FCSエラーや衝突（Late Collision）の原因となります [8, 9]。

2. CSMA/CDと衝突ドメイン

イーサネットは本来共有メディアを想定しており、信号の衝突（Collision）が発生します [10]。

  • CSMA/CD： 衝突を最小化し、発生時に再送を制御するためのアルゴリズムです [10]。
  • 衝突ドメイン： 信号が衝突する可能性のあるデバイスのセットです。ハブは全体で1つの衝突ドメインを作りますが、スイッチはポートごとに独立した衝突ドメインを作成します [11, 12]。
  • フレームバッファリング： スイッチはメモリバッファにフレームを保存することで、異なるポートからの同時送信による衝突を回避します [7, 12]。

3. イーサネット・レイヤ2：フレーム形式とアドレス

イーサネットには歴史的に複数のフレーム形式が存在します [13]。

  • DIX (Ethernet V2)： デジタル、インテル、ゼロックスによって開発された形式で、プロトコルタイプフィールドを持ちます [13, 14]。
  • IEEE 802.3： IEEEによって標準化された形式で、長さフィールドを持ちます [13, 15]。
  • SNAP： 802.2 LLCヘッダーの後に続くサブネットワークアクセスプロトコルヘッダーです [13, 16]。

イーサネットアドレス (MACアドレス) [17]:

タイプ説明
ユニキャスト単一のインターフェースを表します。I/Gビットは0です [17]。
ブロードキャストLAN上の全デバイス宛（FFFF.FFFF.FFFF）です [17]。
マルチキャスト特定のグループ宛で、I/Gビットは1になります [17]。

最初の3バイトはOUI (Organizationally Unique Identifier)と呼ばれ、IEEEが各ベンダーに割り当てます [18]。

4. スイッチング・ロジックと内部処理

スイッチの最終目標は、宛先MACアドレスに基づいてフレームを適切なポートに届けることです [19]。

  • 学習： 受信フレームの送信元アドレスを読み取り、MACアドレステーブルを構築します [20, 21]。
  • 転送： 宛先アドレスがテーブルにあれば該当ポートへ転送し、不明なユニキャストやブロードキャストの場合は、受信ポート以外の全ポートからフラッディングします [20, 22]。

内部処理方式 [23, 24]:

  • ストアアンドフォワード： 全ビットを受信してからFCSチェックを行い、エラーがなければ転送します [23]。
  • カットスルー： 宛先アドレスを受信した直後に転送を開始し、遅延を最小化します [23]。
  • フラグメントフリー： 最初の64バイトを受信（衝突の有無を確認）してから転送を開始します [24]。

5. SPANとRSPAN

監視や分析のためにトラフィックをコピーする機能です [25]。

  • SPAN (Switch Port Analyzer)： ソースポートまたはVLANのトラフィックを、同一スイッチ内の宛先ポートにコピーします [25]。
  • RSPAN (Remote SPAN)： 複数のスイッチにまたがる監視を可能にします。トラフィックは専用のRSPAN VLANを通じて転送されます [26, 27]。

基本設定コマンド例

! ポートの速度とデュプレックスの設定 [6]
interface fastethernet 0/13
 speed 100
 duplex full

! SPANの設定例 [28]
monitor session 1 source interface fa0/12
monitor session 1 destination interface fa0/24

Chapter 2: Virtual LANs and VLAN Trunking

VLANは、1つの物理的なネットワークを論理的な複数のブロードキャストドメインに分割します [1]。本章では、VLANの構成、VTP、トランキングプロトコル、およびPPPoEについて学びます。

1. VLANの構成と範囲

Ciscoスイッチでは、主に以下の2つの方法でVLANを作成・管理します。

  • VLANデータベースモード: 特権モードからvlan databaseコマンドで入る古い管理モードです [2, 3]。作成した情報はFlash内のvlan.datに保存されます [2, 4]。
  • 設定モード (Global Configuration): vlan [ID]コマンドを使用します [5, 6]。また、インターフェースでswitchport access vlan [ID]を実行した際にVLANが存在しない場合、自動的に作成されます [5]。

VLAN番号の範囲 [7, 8]:

範囲VLAN ID説明
標準範囲1 – 1005VTPで伝播可能。1002-1005はFDDI/Token Ring用 [4]。
拡張範囲1006 – 4094VTPトランスペアレントモードでのみ設定可能。VTP v1/v2では伝播されません [7]。

2. プライベートVLAN (Private VLANs)

IPサブネットを節約しつつ、同一VLAN内のポート間通信を制限してセキュリティを高める機能です [1]。

  • プライマリVLAN: 二次VLANをグループ化する親のVLANです [9]。
  • セカンダリVLAN [9, 10]:
    • コミュニティ (Community): 同じコミュニティ内のポート間、および無差別ポート（Promiscuous port）と通信可能です。
    • 孤立 (Isolated): 無差別ポートとのみ通信可能です。同じ孤立VLAN内の他のポートとは通信できません。

3. VLANトランキングプロトコル (VTP)

スイッチ間でVLAN情報を動的に共有するためのプロトコルです [10]。

  • VTPモード [11]:
    • サーバーモード: VLANの作成・変更・削除が可能で、他のスイッチに通知します。
    • クライアントモード: 自身でVLAN変更はできず、サーバーからの通知に同期します。
    • トランスペアレントモード: 受信したVTP情報を転送しますが、自身のVLANデータベースには反映しません。
  • リビジョン番号: VLAN構成が変更されるたびにカウントアップされます [12]。番号が大きい（新しい）情報が優先されるため、中古スイッチの導入時にはリビジョンを0にリセットする注意が必要です [13]。
  • VTPプルーニング: トラフィックが必要ないスイッチへのVLAN転送を抑制し、帯域を節約します [8]。

4. VLANトランキング：ISLと802.1Q

複数のVLANトラフィックを1本のリンクで運ぶための仕組みです [14]。

  • ISL (Inter-Switch Link): Cisco独自のプロトコルで、元のフレームを26バイトのヘッダーと4バイトのトレーラでカプセル化します [14, 15]。
  • IEEE 802.1Q: 標準プロトコルで、フレームに4バイトのタグを挿入します [15, 16]。ネイティブVLAN（デフォルトはVLAN 1）をサポートし、そのVLANのフレームにはタグを付けません [17]。
  • DTP (Dynamic Trunking Protocol): トランクの形成を自動交渉します [15]。desirable（能動的）やauto（受動的）などのモードがあります [18, 19]。

5. 高度な機能とPPPoE

  • 802.1Q-in-Q トンネリング: サービスプロバイダーが顧客のVLANタグを保持したまま、自社のVLANタグを重ねて転送する技術です [20, 21]。
  • PPPoE (PPP over Ethernet): イーサネット上でPPP接続を実現します [22]。エッジルーターでdialerインターフェースを構成し、物理ポートをpppoe-clientとして関連付けます [22, 23]。

基本設定コマンド例

! VLANの作成
vlan 21
 name Marketing

! インターフェースをVLANに割り当て
interface fastethernet 0/3
 switchport mode access
 switchport access vlan 21

! トランクの設定
interface fastethernet 0/12
 switchport trunk encapsulation dot1q
 switchport mode trunk

! VTPの設定
vtp domain CCIE-domain
vtp mode server

Chapter 3: Spanning Tree Protocol

スパニングツリープロトコル (STP) は、レイヤ2ネットワークにおいてループフリーなトポロジを維持するための重要なプロトコルです [1]。本章では、802.1d STPの基本動作から、高速化機能、保護機能、およびEtherChannelについて学びます。

1. 802.1d STP の基本動作

STPはBPDU（Bridge Protocol Data Unit）と呼ばれる制御メッセージを交換し、以下の3ステップでポートの役割を決定します [2, 3]。

  • ルートブリッジの選定: ブリッジID（プライオリティ + MACアドレス）が最も低いスイッチがルートになります [2]。
  • ルートポート (RP) の決定: 各非ルートスイッチにおいて、ルートブリッジへのパスコストが最も低い1つのポートです [2, 4]。
  • 指定ポート (DP) の決定: 各セグメントにおいて、ルートへのパスコストが最も低いハローを送信するポートです [3, 5]。
  • 非指定ポート: RPでもDPでもないポートは「ブロッキング」状態となり、データ転送を行いません [1, 6]。

2. トポロジの変化と状態遷移

障害を検知すると、スイッチはTCN（Topology Change Notification）BPDUをルートへ送り、ネットワーク全体のCAM（MACアドレス）テーブルのタイマーを短縮して再学習を促します [8, 9]。

  • 状態遷移: ブロッキング → リスニング (15秒) → ラーニング (15秒) → フォワーディング [9, 10]。
  • タイマー初期値: Hello (2秒)、Forward Delay (15秒)、Max Age (20秒) [11, 12]。

3. STPの最適化と高度なプロトコル

  • Cisco独自の高速化機能:
    • PortFast: エッジポート（PC接続用）を即座にフォワーディング状態にします [13, 14]。
    • UplinkFast: アクセススイッチのルートポート障害時に、代替ポートへ即座に切り替えます [13, 15]。
    • BackboneFast: 間接的なリンク障害を検知し、Max Ageの待機を省略します [13, 14]。
  • Rapid STP (802.1w): 収束時間を大幅に短縮した標準プロトコル。ポート状態を「Discarding, Learning, Forwarding」の3つに集約します [16, 17]。
  • Multiple STP (802.1s): 複数のVLANをインスタンスにまとめ、スイッチのCPU負荷を軽減します [18-20]。

4. STPの保護機能

意図しない接続や攻撃からトポロジを守るための機能です [21]。

  • BPDU Guard: PortFast設定ポートでBPDUを受信すると、ポートをerr-disabled状態にして遮断します [22]。
  • Root Guard: そのポートの先にあるスイッチがルートブリッジになるのを防ぎます [22]。
  • Loop Guard / UDLD: 片方向リンク障害による意図しないフォワーディング状態への移行（ループ発生）を防止します [23-25]。

5. EtherChannel (PortChannels)

複数の物理リンクを1つの論理リンクとして束ね、帯域拡大と冗長性を確保します [26]。

  • PAgP (Cisco独自): モードは desirable / auto [27, 28]。
  • LACP (802.1AD): 標準プロトコル。モードは active / passive [27, 28]。

基本設定コマンド例

! ルートブリッジの優先度設定
spanning-tree vlan 1 priority 4096

! PortFastとBPDU Guardの設定
interface fastethernet 0/10
 spanning-tree portfast
 spanning-tree bpduguard enable

! LACPによるEtherChannel設定
interface range fa0/1 - 2
 channel-group 1 mode active
interface port-channel 1
 switchport mode trunk

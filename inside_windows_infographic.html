CHAPTER 2 // 設計思想
Windows NT 以来の5つの設計目標（1989年策定）
🔌
拡張性
市場の変化に合わせてコードを柔軟に追加・変更可能にする
🔄
ポータビリティ
x86 / x64 / ARM 等の複数ハードウェアで稼働可能にする
🛡️
信頼性・堅牢性
誤動作・改ざんからシステムを保護し、アプリがOSを損なわないようにする
🔗
互換性
旧Windows / MS-DOS / UNIX 等との互換・相互運用性を確保する
⚡
パフォーマンス
各プラットフォームで可能な限り高速・応答性の良い動作を実現する
CHAPTER 3 // 実行モード
プロセッサのアクセスモード — Ring 構造
Ring 3 — User Mode
Ring 0 — Kernel Mode
Executive
Kernel Core
ユーザーモード（Ring 3）
アプリケーションが実行される非特権モード。システムデータへの直接アクセス・ハードウェア操作は制限される
カーネルモード（Ring 0）
OSコード（システムサービス・デバイスドライバー等）が実行される特権モード。全メモリ・CPU命令にアクセス可能
モード遷移
ユーザーアプリがシステムリソースを必要とする際、システムサービスコールを通じてカーネルモードへ遷移（コンテキストスイッチとは異なる）
HAL（最下層）
ハードウェア固有の差異を吸収し、OSの上位レイヤーから隠蔽する

CHAPTER 5 // 実行単位
プロセス・スレッド・ジョブの階層モデル
📦
ジョブ (Job)
複数プロセスを単一ユニットとして管理・制限するオブジェクト
CPU時間・メモリ・プロセス数などを一括制御
🗂️
プロセス (Process)
プログラム実行のための「リソースコンテナー」
プライベート仮想アドレス空間
オープンされたハンドルのリスト
セキュリティコンテキスト（トークン）
1つ以上のスレッドを内包
🧵
スレッド (Thread)
Windowsが実行をスケジュールする実体
独自のスタック
CPUレジスタの状態（コンテキスト）
スレッドローカルストレージ（TLS）
🔑 OSがスケジュールするのはプロセスではなくスレッド。プロセスはリソースの器であり、実際の実行単位はスレッドである。
CHAPTER 6 // セキュリティ
仮想化ベースのセキュリティ（VBS）— Hyper-V による多層防御
VTL 1 — 高信頼環境
セキュアカーネル
Securekernel.exe が動作する隔離空間。VTL 0 からのアクセスをハイパーバイザーが物理的にブロック
資格情報ガード（Credential Guard）
ドメイン資格情報の隔離保管
デバイスガード（HVCI）
コード整合性の強制
VTL 0 — 通常OS環境
通常カーネル
従来のWindows OS が動作。万が一カーネルモードが侵害されても VTL 1 の資産は保護される
User Mode アプリ
Windows Executive
デバイスドライバー
通常のカーネル処理
🔒 VTL 0 は VTL 1 のメモリに直接アクセス不可 — ハイパーバイザーが分離を強制
✅ 資格情報ガード
ドメイン資格情報を VTL 1 内に隔離。カーネルが侵害されても Pass-the-Hash 攻撃を防止
✅ デバイスガード（HVCI）
ハイパーバイザーによるコード整合性チェック。未署名・改ざんされたコードの実行を物理的に防止
✅ 多層アーキテクチャ
従来のユーザー/カーネルの2層に加え、VTL による第3の分離層を追加。攻撃面を根本的に縮小
CHAPTER 7 // 調査ツール
内部構造を「見る」ためのツール群

ソースコードがなくても、これらのツールでWindowsの挙動を詳細に観察・理解できる

Process Explorer
プロセス・ハンドルの詳細表示。DLLやネットワーク接続も確認可能。タスクマネージャーの上位版
Process Monitor
ファイル・レジストリ・スレッドのリアルタイム追跡。トラブルシューティングの定番ツール
WinDbg
カーネルデバッガー。dt コマンドで構造体の型情報を表示。稼働中システムの深層調査が可能
LiveKd
デバッグモード不要で稼働中カーネルを調査可能にするツール。本番環境の診断に有用
perfmon
パフォーマンスモニター。システム・プロセスの動的パフォーマンス情報をリアルタイム取得
Sysinternals Suite
上記を含む包括的ツール群。マイクロソフト公式提供。Windows 内部理解の必携セット
